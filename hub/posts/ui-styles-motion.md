# 让 WPF 不像 WPF：四套界面风格与一次动画体系重构

WPF 做出来的界面有个通病：能用，但一眼就能认出是 WPF。过渡生硬、悬停是瞬变、控件之间毫无呼应。

10 月 1 日这一天，我们从「界面风格系统」开始，最后落到一次动画体系重构。中间隔了 12 小时，也隔了两次自我修复。

## 01:05 — 一套代码，三种长相

第一件事是把「界面风格」变成一个可切换的维度，而不是写死的外观。

新增 `UiStyle` 注册表，三个值：`standard`（标准）/ `android`（安卓式）/ `glass`（毛玻璃）。`ThemeManager` 持久化风格并在切换时抛事件；`ApplyTheme` 之后**再叠加**对应风格的资源字典，保证主题切换不会把风格覆盖掉。

安卓式风格的实际差异不小：隐藏顶部四色索引贴，改成底部导航栏，胶囊状高亮配强调色。等于同一套页面要适配两种导航结构。

## 01:15 — 顺手把触屏模式做了

十分钟后，触屏模式落地。

- 模型层：`TouchControlConfig` / `TouchButtonConfig`，默认 W/A/S/D 十字方向键 + 空格跳跃
- 发送层：`GameKeySender` 优先用 `PostMessage` 直投游戏窗口，回退 `keybd_event`。为什么要前者？因为面板抢到焦点时，`keybd_event` 发的键未必落在游戏上
- 窗口层：`TouchOverlayWindow` 随游戏进程显示、退出关闭，顶部把手可拖动
- 编辑层：`TouchLayoutEditorWindow`，拖按键、增删、改键码、改大小、调面板尺寸与不透明度

## 22:09 — 回到外观页

隔了一整天，补上外观页剩下的四项：8 色点、窗口背景色、毛玻璃开关、侧栏标签开关。

## 23:01 — 动画问题的真正原因

这里才是当天最有价值的部分。

当时收到的反馈是「WPF 的动画稀缺且生硬」。一开始想的是逐个补动画，但判断下来这是**体系问题**，于是按重构做。

两个根因，都很具体：

**生硬** —— WPF 的 `DoubleAnimation` / `ThicknessAnimation` **默认是线性曲线**。而 HTML 里几乎每个过渡都写了 `ease` / `ease-out`。同样是 0.15 秒，线性看着就是机械的。

**稀缺** —— `Style` 的 `Trigger` **默认是瞬变**，没有过渡。HTML 里处处都是 `transition: .12s~.2s`，WPF 要显式写 `EnterActions` / `ExitActions` 的 `Storyboard` 才有。

第一批做了两件事：

新增 `Themes/Motion.xaml` 作为统一动效令牌：`MotionEase` / `MotionEaseInOut` / `MotionEaseSoft` / `MotionEaseBack`，以及和 HTML 一一对应的四档时长（`.12` / `.15` / `.20` / `.38`）。它必须排在 `MergedDictionaries` **最前面**——令牌类资源优先级最低，不能覆盖主题和控件样式。

然后给全局 Button 补悬停过渡。这里有个必须绕开的坑：

```csharp
// 错：直接动画 Background / BorderBrush
// 它们来自 DynamicResource，是合并字典里的共享画刷
// 动画会抛「无法冻结 / 已被冻结」

// 对：改用一层 Opacity 过渡的高亮蒙版
// 既拿到平滑过渡，又完全不碰共享画刷
```

悬停 0.15s 淡入、移出 0.12s 淡出，走 `MotionEase`。

## 23:10 — 第二批，先修第一批的 bug

按计划补控件过渡：`PrimaryButton` / `GhostButton` / `Card`（上浮 -6px 补缓动）/ `ToggleSwitch` / `ToggleChip` / `ComboBox`（展开时箭头旋转 180°）/ `ComboBoxItem` / `ListBoxItem`（此前只有一个 Foreground Setter，靠系统默认模板）。

但开盘第一件事是修第一批埋的雷：

> HoverMask 放在了 `ContentPresenter` **之后**，z 序更高。而 `ControlHoverBackground` 是**不透明**色（亮 `#F0F0F0` / 暗 `#252830`）——鼠标一悬停，按钮上的字就被整片盖掉了。

修法不是调颜色，是定顺序：**底 → 状态蒙版 → 内容**。本批所有蒙版都按这个顺序写。

侧栏还有个小设计：悬停底和选中底拆成**两层独立蒙版**。这样鼠标划过选中项再离开，不会把选中态一起灭掉。

## 23:25 — 毛玻璃的两个细节

最后补毛玻璃不透明度可配置（滑块 30–100%，默认 75，实时预览）。

关键在**层数控制**。以当前主题窗口底的不透明度为基准，把目标 key 的 alpha 等比缩放。作用范围严格限制在外壳——标题栏 / 状态栏 / 侧栏 / 内容区底 / 浏览器式页签。页面内的卡片和控件底**不跟随**。

结果是「卡片叠在内容底上」恒为两层。调不透明度不会把重叠区域越叠越暗，卡片上的文字可读性也不受滑块影响。默认 75% 恰好还原设计稿原值。

顺手修了两个小问题：

- 玻璃页签压住品牌文字（品牌列宽 = 文字宽，第一个页签左边缘紧贴文字右端）→ 给 TabPanel 让出 16px 左边距，并在 `RestoreDefaultChrome` 里复位，避免边距残留到其他风格
- `SettingsViewModel.GlassOpacity` 用 `double` 而不是 `int`——`Slider.Value` 是 double，绑 int 会走类型转换，拖动时疯狂刷绑定错误日志

还撞了一次老坑：`GridAppearance` 从 12 行补到 13 行，**加了行但没加 `RowDefinition`**。这是这个项目里的第 N 次了。
