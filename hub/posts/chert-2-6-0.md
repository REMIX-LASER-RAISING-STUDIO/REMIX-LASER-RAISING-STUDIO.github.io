# 燧石启动器 2.6.0 内测：服务器复用、HUD 自愈与 Ollama 镜像

先说清楚：**2.6.0 现在还是内测，没有正式发布**。

内测包已经在手上跑，功能基本定型，但版本号、文案、边界情况都还可能改。所以这篇不是发布公告，只是一份「这段时间在改什么」的记录——万一你拿到内测包，也知道该往哪儿看。

## 一、点服务器加入时，别再开第二个游戏

以前从服务器列表点「加入」，逻辑很直白：拼一条启动命令，起一个新进程。问题是你已经开着游戏的时候，它照样起第二个——Minecraft 双开不总是能善终，尤其是同一个账号。

内测版的顺序是：

1. 先查进程注册表里有没有活着的实例；
2. 有的话把游戏窗口提到前台，直接向控制台发 `/connect <address>`；
3. 一个都没有，才走完整的启动流程。

这样「加入服务器」变成一次真正的切换，而不是一次重启。代价是要能可靠地拿到窗口句柄——这就引出了下一条。

## 二、HUD 抓不到游戏进程时，自己重试

HUD 和触屏面板是贴在游戏窗口上的浮层。原来的实现是启动时抓一次进程，抓不到就永久失效，只能重启启动器。

内测版改成自愈：定时器每轮检查当前绑定的进程是否还有效，没有就重新扫一遍游戏进程列表。游戏退出时也先尝试重绑一次，确实没有才关闭浮层。

一个容易踩的细节：浮层窗口**不能**把 WPF 的 `Window.Owner` 指向主窗口。那会让点击浮层时启动器一起被置顶，游戏立刻失焦。正确做法是拿到游戏窗口句柄后绑原生 owner：

```csharp
var hwnd = GameKeySender.FindGameWindow(process);   // 阻塞调用，放后台线程
new WindowInteropHelper(this).Owner = hwnd;
```

`FindGameWindow` 是阻塞的，必须放在 `Task.Run` 里，否则界面会卡住几百毫秒——正好卡在你最想点的那一下。

## 三、启动器退出，浮层一起退

浮层是独立窗口，以前主窗口关闭后它们会留在屏幕上，看起来像程序没退干净。

修法很朴素：在主窗口的 `Closing` 事件里，把两个浮层挨个关掉。注意要派发到各自的 UI 线程：

```csharp
Closing += (_, __) => {
    HudOverlayWindow.Instance?.Dispatcher.Invoke(() => HudOverlayWindow.Instance.Close());
    TouchOverlayWindow.Instance?.Dispatcher.Invoke(() => TouchOverlayWindow.Instance.Close());
};
```

## 四、Ollama 拉模型慢，可以换镜像

内置 AI 助手用 Ollama 跑本地模型。官方源在国内经常龟速，甚至直接断。内测版加了两个可配置项：

- **模型注册表镜像**：拉模型时通过 `OLLAMA_REGISTRY` 环境变量指到镜像。
- **安装器镜像**：一键安装 Ollama 时，从镜像地址下载安装包。

默认仍然是官方源，不动配置的人行为完全不变；需要的自己在设置里填地址即可。

## 内测范围与已知问题

以下是内测版**明确还没处理完**的部分，别当成 bug 报：

| 项目 | 状态 |
| --- | --- |
| 服务器复用 | 单人实例已覆盖，多实例并发抢占仍在观察 |
| HUD 自愈 | 正常路径可用；极小概率出现重绑后浮层位置偏移 |
| 退出联动 | 已完成 |
| Ollama 镜像 | 仅验证了模型拉取与安装器下载两个入口 |
| 多语言文案 | 中文已定稿，繁中与英文待校对 |

内测包安装会覆盖旧版配置目录里的部分设置项，测试前建议先备份 `.minecraft` 以外的配置文件夹。

## 什么时候算发布

等这几件事做完再谈正式版：多实例抢占复现稳定、浮层偏移修掉、英繁两套文案过一遍、更新源从内测通道切回正式通道。

在那之前，2.5.x 仍然是给所有人用的稳定版本。想尝鲜的可以先拿内测包，但别装在主力环境上——这句话不是客气。
