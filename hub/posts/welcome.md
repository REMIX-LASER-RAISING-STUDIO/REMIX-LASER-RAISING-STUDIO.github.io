# 成员博客上线：这里写什么，怎么投稿

RLRS Hub 的成员博客今天开张。这个页面不是又一个产品落地页，而是我们自己的**技术写作区**——写给人看，也写给三个月后的自己看。

## 这里写什么

- **开发日志**：某个功能为什么这么设计，中途推翻了什么方案。
- **踩坑记录**：WPF 的动画接管属性、畸形换行符、CI 的镜像超时，凡是查了两小时以上的都值得写。
- **项目复盘**：发版之后回头看，哪里估算错了。
- **随笔**：跟技术有关就行，不必是教程。

不接受的内容很简单：与项目无关的推广、没有验证过的“经验”、以及任何涉及他人隐私的东西。

## 投稿方式

文章是真·Markdown 文件，直接进仓库：

1. 在 `hub/posts/` 下新建一个 `.md` 文件，文件名用英文短横线，例如 `wpf-animation-pitfalls.md`。
2. 打开 `hub/posts/index.json`，在 `posts` 数组里追加一条：

```json
{
  "slug": "wpf-animation-pitfalls",
  "title": "WPF 动画把属性永久接管之后",
  "author": "你的名字",
  "date": "2026-11-02",
  "tags": ["WPF", "踩坑"],
  "excerpt": "一句话摘要，会显示在专栏列表里。",
  "file": "posts/wpf-animation-pitfalls.md"
}
```

3. 提 PR 或直接推送，合并后专栏列表和文章页都会自动出现，不需要改任何 HTML。

`slug` 是文章地址里用的短名（`/hub/post.html?p=wpf-animation-pitfalls`），一经发布不要改，否则旧链接会失效。

写技术内容时，尽量把**当时的信息**留下：报错原文、版本号、试过但没用的方案。这些细节对后来的人（包括你自己）比结论更有用。
