# 给启动器装个音乐播放器：歌词、六个音源与一次翻唱事故

启动器里放音乐，本来就是件不务正业的事。但既然做了，就得把歌词对上。

这段从 10 月 3 日做到 10 月 6 日，三天。

## 第一步：模式与状态先闭环

10 月 3 日 15:03。先不碰界面，只做能独立验证的核心。

`MusicClientPrefs` 存四件事：总开关、宽限期（0–30 分钟，**0 表示不自动关闭**）、歌词固定方式、客户端模式下是否仍用 API 取歌词。

歌模式分三种：`Api`（音源）/ `LocalFolder`（本地目录）/ `LocalClient`（外部客户端）。

`MusicModeManager` 有两处细节是对的：

- 切模式时先停掉上一个音源，**保证同一时间只有一个在放**，否则启动器和外部客户端会叠音
- 总开关关闭时切到 `LocalClient` **降级为 `Api`**，因为总开关的语义就是「不接管外部客户端」

还有一个容易被忽略的：`Normalized()` 容错。配置可能被手改、来自旧版本、跨设备同步——不归一，`宽限期 9999 分钟` 就会渗进业务逻辑。

## 第二步：歌词引擎

15:19。LRC 解析看起来简单，实际上有一堆边界。

支持三种时间戳格式（`mm:ss.xx` / `mm:ss` / `hh:mm:ss.xx`），跳过 metadata 行（`[ti:]` `[ar:]` `[offset:]`），跳过没有时间戳的裸文本。有三个决定值得说：

**一行多时间戳要展开。** `[00:01.00][00:31.00][01:01.00]词` 是三行，不是一行。

**空正文要保留。** `[00:05.00]` 单独一个时间戳是对间奏占位，保留成空白行，渲染出来就是空行。

**查找用二分。** 歌词动辄几百行，每帧线性扫一遍是浪费。取「最后一个 `TimeSec ≤ t`」，O(log n)。

二分带出一个歧义：多行同一个时间戳时，谁胜出？按 LRC 语义是**后一行覆盖前者**。这个行为被测试固化了，不然以后谁改都得猜。

偏移量（`OffsetMs`）字段和逻辑先做好，但本期不给 UI 入口。正值表示歌词提前，负值延后，统一走 `positionSec + OffsetMs / 1000.0`。

## 第三步：在线歌词，以及一次翻唱事故

17:53。引擎只能解析本地 `.lrc`，「客户端模式下仍用 API 取歌词」这个设置有数据源了。

新增 `ILyricProvider` 抽象加一个网易云实现，走 `/api/search/get` 和 `/api/song/lyric` 两个公开接口，不需要鉴权，返回体直接就是标准 LRC。

然后撞上了一件事，我认为是这段里最值钱的发现：

> 搜索「晴天 周杰伦」，不按歌手过滤的话，会命中「晴天(深情版)」，歌手是 Lucky小爱。

那份歌词和正在播的歌**毫无关系**。而且它比没有歌词更糟——用户会以为播放器出问题了，或者以为这首歌就是这词。

修法是结果按歌手过滤：歌手相符才优先采用，没有相符的才退到首个结果。

另外两个决定：

- 所有失败路径返回 `null`，调用方静默隐藏歌词区。接口是非官方的，改版就可能失效，失败不该变成用户可见的错误
- 请求必须带移动端 UA 加 Referer，否则网易云经常返回空 body

实测「晴天/周杰伦」拿到 44 行，首行是「制作人 : 周杰伦」，确认不是翻唱版；二次调用 0ms 命中缓存。

## 第四步：音源，从一家到六家

10 月 5 日凌晨 01:31。接上在线音源 API：搜索、歌单、扫码登录。

做了两套协议实现：`MetingMusicProvider`（聚合协议，免登录可搜可播）和 `NeteaseCloudMusicApiProvider`（支持二维码登录和「我的歌单」）。登录凭证混淆后落盘，不明文。

10 月 6 日 00:14，扩到六家平台：网易云 / QQ / 酷狗 / 酷我 / 百度 / 虾米，外加「全部平台」（并发搜六家后轮转交错合并，单家失败不影响整体，全灭才抛真实原因）。

这里有个结构上的坑，必须记下来：

> 聚合搜索返回的曲目来自不同厂家。如果拿网易云的 provider 去给 QQ 的曲目换直链，**必定失败**。

所以 `OnlineTrack` 必须自带 `Platform` 字段，取直链和取歌词都按曲目自己的厂家回源。

接着又抽了一层 `VendorApiProfiles`：路由、默认端口、扫码状态码判读、登录态传递方式，都由厂家声明，provider 只写一份通用实现。

- 网易云 → `NeteaseCloudMusicApi`（3000，已验证的专用实现）
- 酷狗 → `KuGouMusicApi`（3000，状态 0 过期 / 1 待扫 / 2 待确认 / 4 成功）
- QQ → `QQMusicApi` web（8080，`/login/qrcode/qq`，登录态走 Cookie 头）
- 酷我 / 百度 / 虾米 → 没有可用的自建项目，自动退回 Meting

最后一个细节：`MusicApiPrefs` 改成按厂家分桶，每家一份地址和凭证。切换厂家不会串登录态。旧版的单份配置在 `Normalized()` 里迁移。
