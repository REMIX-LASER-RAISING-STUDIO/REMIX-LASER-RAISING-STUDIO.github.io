# 一块皮肤的六个面：3D 预览里的 UV 连环坑

Minecraft 皮肤就一张 64×64 的图，但要在 3D 里铺对，得把这张图切成几十个小块，逐个贴到盒子的六个面上。这段我们改了六次，其中两次是**推翻自己上一次的修法**。

按时间顺序记一遍。

## 起点：旧皮肤的左手是空的

9 月 5 日。第一版 3D 预览做完，导入一张老版 `64×32` 皮肤，左臂和左腿直接不显示。

原因很直白：旧格式的下半部分是空的，左肢纹理区没有像素。原 UV 照着采样，采到的全是透明。

修法是给旧格式加一条回退——左肢去读右肢的纹理区。新增 `LegacySkin` 依赖属性，由编辑器在导入 `64×32` 时置位，切换时重建整个网格。顺手把视口从固定 `200×360` 的小框改成填满预览区。

## 第一次纠正：左右肢内外贴反

9 月 7 日。正视图看着对，转到侧面，左臂的内外两面是反的。

`SkinModel3D.Build` 只把 Left/Right 纹理固定贴到 `-X` / `+X` 面，这套映射只对 `+X` 侧的肢体成立。左臂在 `-X` 侧时，内外就颠倒了。此外右臂原本放在 `+X`，和原版正面（角色右手在观察者左侧）是镜像关系。

改法是让 `cx` 取负，把右臂右腿挪到 `-X`、左臂左腿挪到 `+X`，然后对 `cx < 0` 的肢体交换 Left/Right UV。

当时觉得这下彻底对了。

## 第二次纠正：底面转了 180°

9 月 10 日。抬头看头底、抬手看手掌，纹理都是倒的。

`-Y` 面的法线指向盒子内部，从外面看到的是背面材质，实测正好转 180°。改法是把底面四角顺序整体反转，只重排顶点和 UV 的对应关系，不动几何——配合双面材质不会丢面。

同一笔还修了左肢内外侧：`AddBox` 固定把 `uv.Right` 贴 `-X`、`uv.Left` 贴 `+X`，但左肢在 `+X` 侧，这套固定映射又是反的。于是又加了一次 Left/Right 交换。

## 第三次：2D 画布偏移了 4 像素

9 月 11 日凌晨。3D 看着正常了，2D 编辑器里腿上移、右手外侧缺图、slim 手异常。

`SkinLayout` 的截取坐标整体偏了 4px（四肢正面 `y=16` 应为 `y=20`），顶帽底帽错位，左肢左右面颠倒。

这次修的是坐标表，让它逐像素对齐 `SkinModel3D` 实际输出的 `LimbUv` / `HeadUv` / `BodyUv` / `HatUv` / `JacketUv`——包括 overlay 的袖子和裤子。目标很明确：**2D 画布和 3D 双层预览必须落到同一块皮肤像素上**。

## 第四次：把上次的交换删了

同一天晚上 23:39。修 slim 手臂时发现问题根源没那么简单。

slim 手臂宽度是 3 而不是 4，收窄的不只是 front/back/top/bottom，`left` / `back` / `bottom` 的 X 坐标也得跟着左移，否则后方和下方会缺一半。

然后发现上一笔加的那个「左肢交换 Left/Right」是**错的**：

> 左肢位于 `+X` 侧，它的 `+X` 面就是外侧，而皮肤的 Left 区本来就是这块外侧的纹理。`+X → uv.Left` 天然正确，交换反而把它贴反了。

于是删掉。同一个位置，两天内加了一次又删了一次。

## 第五次：换行符级别的真凶

9 月 12 日凌晨 01:16。前面都修完了，四肢和躯干纹理还是整体上移，底部多出一块末行颜色的白区。

真因跟 UV 数值一点关系都没有，是 WPF 的 `ImageBrush`：

```csharp
// 默认 ViewportUnits = RelativeToBoundingBox
// TileBrush 按网格 UV 的包围盒填充贴图
// → AddFace 里 uMax / vMax 的 UV 收窄完全失效
```

整张 POT 画布（内容 + 边缘钳制留边）被拉满到每个面上：内容被压到上方 `sh/ph` 的比例，末行的留边被拉伸占满底部。

修法只有两行：

```csharp
Viewport = new Rect(0, 0, 1, 1);
ViewportUnits = BrushMappingMode.Absolute;
```

绝对 UV 空间里，收窄才真正生效。

验证手段值得记一笔：做了一张「UV 解码皮肤」——每个像素的颜色就是它自己的坐标。贴上去之后逐行读颜色，哪一面采样歪了立刻现形。这比盯着成品皮肤看半天靠谱得多。

## 六次修改的时间线

| 时间 | 问题 | 层次 |
| --- | --- | --- |
| 09-05 01:56 | 旧格式左肢无纹理 | 格式兼容 |
| 09-07 00:19 | 左右肢内外贴反 + 镜像 | 几何放置 |
| 09-10 23:30 | 底面 180° 旋转 | 顶点顺序 |
| 09-11 01:43 | 2D 画布偏 4px | 坐标表 |
| 09-11 23:39 | slim 手臂缺半 + 删掉多余交换 | UV 推导 |
| 09-12 01:16 | 纹理整体上移 | 画刷映射 |

六次里只有最后一次是真的「UV 算错了以外的东西」。前面五次都在几何和坐标表上打转，而症状看起来一模一样——都是「纹理位置不对」。

这也是这段最耗人的地方：**同一个症状可以由四个不同层次的 bug 产生**，改完一个，剩下的那个还在，很容易以为自己的修法无效、然后去改本来正确的代码。

真要说经验，只有一条：先把「哪一层错了」定位清楚，再动手。我们花了六次才做到这件事。
